# Как использовался ИИ

Это журнал фактической работы в Codex над проектом, а не придуманная переписка с отдельной командой. Внешние субагенты не запускались. ИИ выполнял проектирование, реализацию и проверки в одном рабочем контексте; пользователь задавал требования и корректировал решения.

## Реальные входные указания

Первый запрос пользователя — техническое задание микро-SaaS: CSV/Excel или текст → AI-нарратив → 2–3 интерактивных графика → чат только по данным; без авторизации и сложного бэкенда. В нём отдельно оценивались UX, AI-логика, delivery и читаемая архитектура.

Последующая коррекция пользователя, дословно:

> интеграция с гигачат

После вопроса о локальном ключе пользователь выбрал:

> Пока проверить без ключа

Эти указания изменили реализацию: первоначально выбранный OpenAI-адаптер был заменён на GigaChat; OpenAI SDK удалён из зависимостей. Live-вызовы не имитировались.

## Решения, которые направляли генерацию кода

Следующие пункты — **описание принятых инженерных решений**, а не цитаты несуществовавших пользовательских промптов:

1. Считать показатели кодом, а GigaChat поручить интерпретацию и выбор допустимых графиков.
2. Сформировать общий каталог фактов с ID и источниками для hero и чата.
3. В чате ограничить модель выбором ID. Сервер выводит исходные подтверждения дословно.
4. Не угадывать причинность, прогнозы и пропущенные значения; честно показывать недостаточность данных.
5. Сначала обеспечить полный пользовательский путь, затем проверить его через браузер и production-сборку.
6. Сделать деморежим полезным для ревью, но заметно отличимым от AI-режима.

## Промпты, реально используемые продуктом

Авторитетный источник — `src/lib/server/prompts.ts`. Схемы ответа — `src/lib/server/analysis.ts`.

Фрагмент промпта hero:

> Составь короткий заголовок и 2–3 предложения о главном наблюдении. Используй ИСКЛЮЧИТЕЛЬНО facts. Укажи evidence: идентификаторы фактов, которые подтверждают ВСЕ утверждения. Не добавляй чисел или причин, которых нет в фактах.

Фрагмент промпта чата:

> Верни answerable=true и от 1 до 4 evidenceIds ТОЛЬКО если эти факты напрямую отвечают на ВЕСЬ вопрос. Приложение покажет факты дословно вместо свободной генерации.

Входной JSON содержит факты, допустимые графики или вопрос. API использует JSON Schema; Zod и серверная логика проверяют результат независимо от промпта.

## Где сгенерированный код пришлось исправить

### Проверка Origin ломала локальный чат

Первая реализация сравнивала заголовок `Origin` с `request.url.origin`. В браузере запрос с `http://localhost:3000` возвращал ошибку «Запрос должен быть отправлен со страницы Lens»: Next.js представлял внутренний URL как `http://0.0.0.0:3000`.

**Исправление:** сравнение origin host с реальным заголовком `Host`, тест легитимного localhost-запроса и тест чужого Origin. После исправления чат в браузере вернул правильные 2 307 заказов.

### Демочат мог слишком широко сопоставлять вопрос

При проверке кода обнаружено: выражение вроде `сколько.*заказ` могло ответить общим итогом на вопрос «Сколько всего заказов в октябре?», хотя пример относится к сентябрю.

**Исправление:** ограниченные полные шаблоны вопросов для деморежима, регрессионная проверка отказа на другой период. Свободные вопросы оставлены GigaChat.

### Визуальные и языковые дефекты

Браузер показал обрезанные подписи Y-оси из-за отрицательного отступа. В заголовке демосводки появилась неграмотная фраза «лидер по выручка». Третий график первоначально показывал одинаковое количество строк по каналам и почти ничего не сообщал.

**Исправление:** обычный отступ оси, нормальный заголовок с рассчитанной долей выручки, сравнение заказов по каналам, увеличение читаемости подписей. Проверен узкий экран без горизонтального переполнения.

### Поиск смешивал соседние идентификаторы

Тест поиска по `LENS-104` вернул и строку `LENS-105`. Причиной было одинаковое усечение последнего символа для слов и идентификаторов.

**Исправление:** упрощённое сопоставление словоформ применяется только к кириллическим словам; ID сопоставляются точно. После исправления тест проходит и возвращает только нужную строку.

### Зависимости требовали актуализации

После первой установки npm сообщил проблемы в ZIP-зависимости и транзитивном UUID. Обновлён `adm-zip`, для ExcelJS задан совместимый UUID 11.1.1 (ExcelJS использует только `v4`). Чтение реального XLSX затем прошло тест. Production-аудит зависимостей не обнаружил известных уязвимостей на момент проверки.

## Что не доказано

- Доступность конкретной модели и качество живых ответов GigaChat: ключ не предоставлялся по решению пользователя.
- Семантическая правильность каждого AI-вывода: валидация чисел и ID снижает риски, но не заменяет набор live-eval.
- Готовность к большим публичным нагрузкам: лимиты и обработка ошибок есть, распределённой квоты и защиты бюджета пока нет.

На демонстрации эти ограничения следует произнести прямо. Не называть mock-тесты проверкой живой модели и не приписывать ИИ вымышленные ошибки.
