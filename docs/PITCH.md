# Видео-питч: 3–5 минут

Ниже сценарий для записи реального экрана в Loom/Vimeo. Открыть Lens, README, `src/lib/server/prompts.ts`, `docs/AI-WORKLOG.md`. Не показывать `.env.local`, терминальные токены или личные вкладки.

## 0:00–0:35 — продукт и рамки

«Это Lens — сервис, который превращает таблицу или заметки команды в понятную историю. Он сразу открывается без регистрации. Встроенный пример — продажи за сентябрь: главный вывод, показатели и графики уже на экране. Сейчас я показываю явно обозначенный деморежим: API-ключ GigaChat в этой проверке не использовался. Файлы, расчёты и интерфейс при этом настоящие».

## 0:35–1:15 — загрузка и графики

Нажать «Загрузить данные», выбрать `public/examples/sales.xlsx`, показать обработку. Провести мышью по графику, открыть его таблицу значений. Затем перейти в «Данные», найти «Социальные сети».

«Можно загрузить CSV, Excel или вставить обычный текст. Код определяет числовые, временные и категориальные столбцы. Суммы и доли вычисляются детерминированно. При подключённом GigaChat модель выбирает подходящие графики из проверенного каталога, но не придумывает значения. Если в тексте нет сопоставимых чисел, интерфейс объясняет это, а не рисует случайный график».

## 1:15–1:55 — чат и границы знания

Вернуться к обзору. Задать «Сколько всего заказов?», раскрыть подтверждение. Затем спросить «Какая зарплата у директора?».

«Ответ про заказы берётся из отчёта. Вопрос о зарплате получает честный отказ. В AI-режиме модель получает каталог фактов и релевантные строки, выбирает идентификаторы подтверждений. Сервер собирает ответ из этих фактов дословно. Это намеренное ограничение: меньше свободы формулировки, зато модель не может добавить произвольные числа. Ссылки на источник помогают проверить результат. Свободные вопросы требуют подключённого GigaChat; демочат поддерживает только заданные шаблоны».

## 1:55–2:40 — как направлялась работа ИИ

Показать реальные коррекции в `AI-WORKLOG.md`, затем два промпта в `prompts.ts`.

«Код создавался с помощью Codex. Я использовал исходное ТЗ как продуктовый контракт: полный сценарий важнее одной идеальной карточки. После уточнения пользователя провайдер заменён на GigaChat. Ключ было решено пока не подключать, поэтому интеграция проверяется на подменённом транспорте. В промпте hero задано два-три предложения только по фактам. В промпте чата модель должна отказать, если подтверждения не отвечают на весь вопрос. Помимо промптов есть схема ответа и программные проверки».

## 2:40–3:30 — реальные ошибки и исправления

Показать `http.test.ts`, тесты демочата и соответствующие разделы журнала.

«Первый код содержал ошибку Origin: браузер обращался к localhost, а Next видел адрес 0.0.0.0, и чат отказывал своему пользователю. Это нашлось только при проверке в браузере. Проверку исправили и закрепили тестом. Ещё слишком широкий шаблон вопроса мог выдать сентябрьский итог за октябрь. Его сузили и добавили тест отказа. В интерфейсе исправлены обрезанные подписи оси и малоинформативный третий график. Это примеры того, почему сгенерированный код нужно проверять действиями пользователя».

## 3:30–4:10 — архитектура и delivery

Показать структуру README и результат команд проверки.

«Парсинг, расчёты, AI-адаптер и компоненты разделены. Next.js Route Handlers подходят для Vercel, тяжёлого бэкенда нет. Проходят тесты, TypeScript, линтер и production-сборка. Следующий обязательный шаг перед сдачей полноценного AI-сервиса — подключить ключ и проверить живые ответы GigaChat: отсутствие галлюцинаций нельзя объявлять доказанным по mock-тестам. Публичную ссылку нужно закрепить за своим аккаунтом, если используется временный preview. Репозиторий содержит инструкции, примеры и этот честный журнал работы».

## Перед записью финального варианта

- Если уже подключён ключ, загрузить собственный небольшой файл и показать реальный badge GigaChat. Соответственно изменить текст о деморежиме.
- Проверить ссылку в приватном окне без логина, включая POST `/api/analyze` и `/api/chat`.
- Записать 3–5 минут, без ускоренного монтажа, с читаемым масштабом окна.
- Загрузить в Loom/Vimeo с доступом по ссылке и добавить URL в `docs/DELIVERY.md`.
